# UI qcheck — 見た目の品質チェック

pytest では検証できない「見た目」を対象にした、再実行可能な手順書。
各項目は VISION.md の `[qcheck]` 設計思想、またはそのレビュー過程で見つかった
追加の観点に対応する。実施日・結果は各項目の末尾に記録する。

判定記号: ✅ PASS(合格) / ⚠️ FAIL→修正済み / 🔲 未実施(要人手)

---

## QC-UI-01: 見出し・全体レイアウト

**対応する設計思想**: なし(基本UIの健全性チェック)

**手順**:
1. https://juhkioschima.github.io/company-logo-fetcher/ を開く
2. 3つの見出し(「ロゴを取得する」「今回の出力結果」「ストック」)のフォントサイズを確認する
3. コンソールにエラーが出ていないか確認する

**期待結果**: 見出しは20pxで統一され、丸数字(①②③)が付いていない。コンソールにJSエラーが無い。

**実施結果**: ✅ PASS(2026-08-25)
`getComputedStyle` で `h2 { font-size: 20px }` を確認。見出しテキストは
`["ロゴを取得する", "今回の出力結果(0社)", "ストック(34社)"]` で丸数字なし。
`read_console_messages` でエラーなし。

## QC-UI-04: ボタンの配色(コミット系・削除系・PPTX系)

**対応する設計思想**: ユーザー指定「PPTXに出力・ストックから削除ボタンを分かりやすい色に」

**手順**: 各ボタンの `background-color` を計算スタイルで確認する

**期待結果**:
- 「PPTXに出力」= 青(primary)
- 「ストックから削除」= 赤(danger、不可逆操作の警告色)
- 「まとめてやり直し」= 他の2色と衝突しない第三の色(注意喚起だが不可逆ではない)

**実施結果**: ⚠️ FAIL→修正済み(2026-08-25)
「PPTXに出力」`rgb(0,95,184)` と「ストックから削除」`rgb(176,0,32)` は指示通り。
一方「まとめてやり直し」ボタンが白背景のまま(デフォルト)で、色分けの一貫性が
崩れていた(発見時点では未着手のボタンだったため)。`button.warn`
(琥珀色 `#b45300`)を追加して是正。再検証で `rgb(180, 83, 0)` を確認。

## QC-UI-08: PPTXレイアウト(実際にPowerPointで開けること)

**対応する設計思想**: 機能別ルール「全ロゴを1スライドにグリッド配置し…実際にPowerPointで開けること」`[qcheck]`

**手順**:
1. `tools/pptx_paste_matrix.py` 相当の COM 自動化で、ブラウザ内生成(`docs/index.html` の
   `buildPptx()`)と Python 側生成(`src/pptx_export.py` / `tools/ci_fetch.py`)の両方を
   実際に PowerPoint で開き、スライド数・図形数を確認する
2. スクリーンショットを比較する

**期待結果**: 例外なく開け、ロゴ画像とラベルが指定のグリッドで配置されている

**実施結果**: ✅ PASS(2026-08-25 に実機検証済み、本セッションではコード同一性で回帰確認)
過去のセッションで、ブラウザ生成 PPTX を実際に PowerPoint で開き
(`cache/pptx_lab/mine_fixed.pptx` → `mine_fixed.png`)、トヨタ自動車・ソニーグループの
ロゴとラベルが正しいグリッドで表示されることをスクリーンショットで確認済み
(不具合: `slideLayout` への `rId1` 関連付け欠如で開けない → 修正)。
本セッションで `docs/index.html` の該当コード(`buildPptx`/`slideXml`/rels生成)を
再読し、修正済みのコード(`rId1`→slideLayout、画像は`rId2`以降)が
**そのまま維持されていること**を確認した(バイト単位のバイナリ再転送・再検証は
このブラウザツールでは大容量データの往復が不安定なため省略)。
Python側(`src/pptx_export.py`)は `tests/test_pptx_export.py` で
python-pptx を使った構造検証済み(pytest, 5件PASS)。

## QC-UI-09: クリップボード形式(exe/GUI版、PowerPointへの貼り付け)

**対応する設計思想**: 機能別ルール(クリップボード連携)「PNG形式 + CF_HDROP(ファイル) +
CF_DIB(白背景の保険)の組み合わせを使う。CF_DIBV5は絶対に載せない」`[qcheck]`
(実機のPowerPoint COM自動化で検証、pytestの対象外)

**手順**: `python tools\verify_copy_combo.py` を実行する。実際に PowerPoint を COM 起動し、
サンプル画像(透過+半透明を含む)をクリップボード経由で貼り付け、結果をスライドから
画像として書き出して画素を判定する。

**期待結果**: 標準出力に `透過部: 保持` `半透明部: フルアルファ` `判定: PASS` が出る

**実施結果**: ✅ PASS(2026-08-25、本セッションで再実行し再確認)
```
載せた形式: PNG, CF_DIB(白背景), CF_HDROP(ファイル)
透過部: 保持
半透明部: フルアルファ
判定: PASS
```
